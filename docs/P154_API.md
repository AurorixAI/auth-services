# #154 «Разовые уроки: отработка / дополнительный» — контракт сервера (auth)

Ветка `p154` (auth-service-p154). Префикс всех путей — `/api/v1/auth`. Ошибки — `{"detail": {"code", "message", ...}}`, кроме отмеченных «текстом» (`{"detail": "<текст>"}`, 400/403 как раньше).
Версия 4 — после выпуска #154 и пакета #159 (29.10); изменения против v1–v3 — в конце файла («Журнал изменений контракта»). Примеры и тексты сверены с тестами `tests/test_p154_create_pg.py`, `tests/test_p154_money_pg.py` и `tests/test_p159_money_pg.py`.

## 0. Правила (коротко)

- Вид разового урока — колонка `purpose`: `makeup` (отработка) / `extra` (дополнительный) / `moved` (копия переноса; создаётся только переносом).
- Дополнительный (`extra`) ученикам бесплатен при любом способе оплаты, пропуск на нём ничего не стоит. Преподавателю: `money` = `none` (без оплаты) / `wait` (просит оплатить; решает владелец или админ **с правом денег** после проведения) / `paid`.
- **Право денег (v4)** — существующая настройка `organizations.settings.payments.admin_can_manage` (в профиле `payments_access`; новых настроек нет). Деньги преподавателю решает владелец и админ с правом; админ без права ведёт себя как преподаватель: `wait` / `none` при создании, `paid` и «Оплатить / Не оплачивать» — 403 `MONEY_RIGHT_REQUIRED`. Право читается из организации в самом запросе, под блокировкой группы (порядок: группа → строка).
- Отработка (`makeup`): деньги как у обычного урока, `money` **всегда `null`** (v4: решения по деньгам у отработки нет, в базе CHECK `ck_one_off_money`); вычет ученику за отменённый урок снимается по факту (отработка проведена и ученик в её составе с отметкой «был / опоздал / не был»; уважительная со справкой — вычет остаётся). Пока отработка впереди или идёт — вычет приостановлен у всех учеников группы.
- Пустая отработка (проведена, ни одного «был / опоздал») — **обычный проведённый урок** (v4): преподавателю идёт в ведомость по отметкам и ставке, как любой урок; ученикам засчитывается («не был» тоже). Ждёт решения только дополнительный `wait`.

## 1. Создание: `POST /org/schedule/occurrences` (было, поля добавлены)

Права: преподаватель своей группы, владелец, админ этого центра (как раньше). Тело — как раньше (`groupId`, `lessonDate`, `startTime`, `endTime`, `room`, `format`, `color`, `topic`) плюс:

| Поле | Тип | Правило |
|---|---|---|
| `purpose` | `"makeup"` \| `"extra"` | Обязательно для владельца/админа (нет → 422 `PURPOSE_REQUIRED`). Преподаватель без поля = `extra` + `wait`. `"moved"` или другое → 422 `PURPOSE_INVALID`. Фронт всегда шлёт явно |
| `money` | `"none"` \| `"wait"` \| `"paid"` | Только при `extra`. Преподаватель: `wait` (по умолчанию) или `none`; `paid` → 422 `MONEY_INVALID`. Владелец и **админ с правом денег**: `none` или `paid` обязательно (нет → 422 `MONEY_REQUIRED`; `wait` → 422 `MONEY_INVALID`). **Админ без права (v4)**: как преподаватель — `wait` (по умолчанию, если поля нет) или `none`; `paid` → **403 `MONEY_RIGHT_REQUIRED`** (создание с `paid` — денежное решение; ничего не записывается). При `makeup` поле должно отсутствовать или быть `null`, иначе 422 `MONEY_INVALID` |
| `madeUpLessonId`, `madeUpDate` (`YYYY-MM-DD`) | строка, дата | Только при `makeup` и обязательны (нет → 422 `MAKEUP_TARGET_REQUIRED`). При `extra` — 422 `MAKEUP_TARGET_NOT_ALLOWED` |

Ответ `201` — прежний (`id`, `groupId`, …, `warnings`, `createdBy`) плюс поля вида (§4).

Ошибки (новые):

| Код | HTTP | Когда |
|---|---|---|
| `TEACHER_REQUIRED` | 422 | у группы нет преподавателя (для `extra` и `makeup`); текст «Выберите преподавателя» |
| `MAKEUP_NOT_ALLOWED` | 422 | отменённый урок отработать нельзя; в `detail.reasonCode` одно из: `NOT_FOUND` (урока нет в расписании группы), `NOT_CANCELLED`, `ONE_OFF` (разовый урок), `HOLIDAY` (отмена как праздник), `NO_KIND` (отмена без вида: старая), `MOVED` (урок перенесён), `TOO_OLD` (оригинал старше 60 дней); `message` — готовый текст |
| `MAKEUP_EXISTS` | 409 | по уроку уже назначена отработка (в т.ч. вторая одновременная попытка) |
| `MOVE_IN_PAST` / `MOVE_TOO_FAR` / `MOVE_SAME_SLOT` / `SERIES_ENDED` | 422 | слот отработки (те же коды и тексты, что у переноса): дата от сегодня до +60 дней, не в то же время, не после прекращения серии |
| `GROUP_BUSY` | 409 | у группы уже есть урок в это время (`detail.conflicts`); **у отработки и у дополнительного**, проверка после блокировки группы (двойной щелчок: второй получит `GROUP_BUSY`) |
| `TEACHER_BUSY` | 409 | преподаватель занят (`detail.conflicts`), как раньше |
| `STUDENT_BUSY` | warning | в `warnings[]` ответа: у ученика другой урок в это время (у отработки и у дополнительного) |
| `NOT_A_MEMBER` | 403 | автор не состоит в этом центре (роль по умолчанию не подставляется) |
| `MONEY_RIGHT_REQUIRED` | 403 | админ без права денег прислал `money = "paid"`; текст «Решение об оплате принимает владелец или администратор с правом на оплаты» (v4) |

Прежние отказы остаются: прошедшая дата / прошедшее время сегодня — 400 текстом (для `extra`); у отработки те же случаи дают 422 `MOVE_IN_PAST` (общая функция с переносом). Группа в архиве — 409 `GROUP_ARCHIVED`.

Кабинет отработки по умолчанию — кабинет отменённого урока (если `room` не прислан).

## 2. Какие уроки можно отработать: `GET /org/groups/{groupId}/makeup-candidates`

Права: владелец/админ любой группы центра; преподаватель — только своей группы (чужая → 403; группа другого центра → 404 `GROUP_NOT_FOUND`). Создание (`POST /org/schedule/occurrences`) для группы другого центра отвечает 400 текстом «Группа не найдена», как раньше.

```json
{
  "items": [
    {"lessonId": "lesson-mon", "lessonDate": "2026-11-02", "startTime": "10:00", "endTime": "11:00", "label": "пн 02.11, 10:00–11:00", "reason": "Преподаватель заболел"}
  ],
  "emptyReason": null
}
```

- Подходят: урок по расписанию (не разовый), отменён «по вине центра», не перенесён, по нему нет отработки, дата не старше 60 дней; группа активна. Сортировка по дате, старые первыми.
- `reason` — текст причины отмены. Владельцу/админу — всегда. Преподавателю — там, где её показывает журнал этого урока (одна функция `AttendanceRules.teacher_sees_lesson`: преподаватель группы видит причины всех уроков своей группы, любой другой — только своего урока не старше «сегодня − 7 дней»); иначе `null`. Список открыт только преподавателю группы, поэтому на деле он видит причины всех своих кандидатов.
- Если список пуст: `items = []` и `emptyReason` — текст для подсказки у неактивного пункта («Нет отменённых уроков, которые можно отработать: …»).

## 3. Решение «Оплатить / Не оплачивать»

Очередь (3.1) и счётчик (3.3) читают владелец и любой админ центра (преподаватель → 403): админ без права видит строки и статус, но решить не может. Решение (3.2) — владелец и админ **с правом денег** (v4). Суммы нигде не отдаются.

### 3.1. `GET /org/one-off-decisions` — ждут решения

```json
{
  "total": 1,
  "items": [{
    "lessonId": "one-off-…", "groupId": "…", "groupName": "7-А",
    "lessonDate": "2026-11-05", "startTime": "16:00", "endTime": "17:00",
    "purpose": "extra",
    "title": "Дополнительный урок — оплатить преподавателю?",
    "teacher": {"id": "…", "name": "Рахимов Т."},
    "createdBy": {"id": "…", "name": "Рахимов Т.", "role": "teacher"},
    "studentsPresent": 3, "studentsTotal": 10,
    "payrollSheet": {"month": "2026-11", "status": "settled"}
  }]
}
```

- Попадают только проведённые уроки (`completed`): `extra` + `wait`. **Отработка не попадает никогда** (v4, в том числе пустая): `purpose` в строках всегда `extra`, `title` = «Дополнительный урок — оплатить преподавателю?».
- `teacher` — кто провёл (снимок `teacher_id` проведённого урока).
- `payrollSheet` — есть ли у этого преподавателя сохранённая ведомость за месяц урока. `null` — ведомости нет. У **владельца** `status` = `unpaid | due | settled | overpaid`; у **админа** `status` всегда `null`, остаётся только `{"month": "…", "status": null}` (правило 45); если у преподавателя за месяц нет сохранённой ведомости — `payrollSheet: null` у обоих. Для окна: если `status` ≠ `unpaid` (или у админа ведомость есть) — предупреждение «Ведомость за <месяц> выплачена — изменится сумма: доплатить или переплата» (текст собирает фронт из `month`).
- Окно 1-го числа и «срочные» на эти строки не действуют (полей `urgent` / `expiring` нет).
- Сортировка: по дате урока, старые первыми.

### 3.2. `POST /org/one-off-lessons/{lessonId}/money-decision`

```json
{"decision": "pay"}        // или "skip"
```

Ответ `200`: `{"lessonId": "…", "money": "paid" | "none", "payrollSheet": {…} | null}` (форма как в 3.1; тот же маскинг).

| Код | HTTP | Когда |
|---|---|---|
| `ONE_OFF_NOT_FOUND` | 404 | нет такого разового урока в этом центре |
| `DECISION_NOT_ALLOWED` | 422 | урок не `extra` + `wait` (отработка, `paid` / `none` с момента создания) |
| `LESSON_NOT_COMPLETED` | 409 | урок ещё не проведён (в т.ч. отменён) |
| `ALREADY_DECIDED` | 409 | решение уже принято (в том числе вторым администратором в гонке); повтор не меняет ничего |
| `DECISION_FORBIDDEN` | 403 | роль в центре не владелец и не админ (роль по умолчанию не подставляется) |
| `MONEY_RIGHT_REQUIRED` | 403 | админ без права денег (право читается под блокировкой группы: снятое право посреди запроса не проходит); `money` и журнал не меняются (v4) |

После «Оплатить»: `money = paid`, в ведомости урок входит в сумму; после «Не оплачивать» — `none`, «без оплаты». В журнал группы пишутся записи `one_off_created` (при создании) и `one_off_money_decided` (решение; `actor_role` — владелец или админ с правом). У отработки `money` всегда `null` (v4): проведённая пустая отработка ничего не ждёт.

### 3.3. Счётчик: `GET /org/substitutions/summary` (было, поля добавлены)

Добавлено: `oneOffDecisionsTotal` (сколько строк в 3.1) и `waitingTotal` = `pendingTotal` + `oneOffDecisionsTotal`. Вкладка «Ждут решения» и бейдж меню показывают `waitingTotal`; `pendingTotal` — по-прежнему только заявки на замену.

## 4. Поля вида в ответах расписания

Во всех трёх местах, где урок отдаётся списком: `GET /org/schedule/occurrences`, журнал группы (`lessons[]` из ответа посещаемости группы) и карточка ученика (`lessons[]` сводки посещаемости ученика) — у разовых уроков (и у отменённых оригиналов) появляются поля:

| Поле | Кому | Значение |
|---|---|---|
| `purpose` | всем | `makeup` \| `extra` \| `moved` \| `null` (у урока по расписанию) |
| `purposeLabel` | всем | «Отработка за пн 03.11» / «Дополнительный» / `null` (у `moved` и урока по расписанию — `null`) |
| `madeUpFor` | всем | у отработки: `{"lessonId", "date", "startTime", "endTime"}` отменённого урока; иначе `null` |
| `madeUpBy` | всем | у отменённого оригинала: `{"lessonId", "date", "startTime", "endTime", "label": "Отработан → чт 06.11"}`; иначе `null` |
| `money` | владелец/админ; преподаватель — только по уроку своей группы или тому, который создал он сам (чужому — `null`); ученик/родитель — никогда | `none` \| `wait` \| `paid` \| `null` (**у отработки всегда `null`**, v4) |
| `moneyLabel` | те же | владелец/админ: «без оплаты» / «оплата: не решено» / «оплачивается»; преподаватель: «без оплаты» / «не решено» / «оплачено»; `null`, если у урока нет `money`. Для ещё не проведённого `wait`: «оплата: решите после урока» (владелец/админ) / «не решено» (преподаватель) |
| `createdBy` | как раньше | `{id, name, role}` автора (копия переноса наследует автора) |

Суммы, ставки и решения (кто и когда решил) в этих ответах не отдаются никому.

## 5. Права: сводка

| Действие | Преподаватель группы | Владелец / админ |
|---|---|---|
| Создать отработку | да, без подтверждения | да |
| Создать дополнительный | `money` = `wait` / `none` | владелец и админ с правом: `money` = `none` / `paid`; админ без права: `wait` / `none` (`paid` → 403 `MONEY_RIGHT_REQUIRED`) |
| Список для отработки | своя группа; причина отмены — как в журнале этого урока | любая группа, с причинами |
| Решить «Оплатить / Не оплачивать» | нет (403) | владелец — да; админ с правом денег — да; админ без права — нет (403 `MONEY_RIGHT_REQUIRED`), очередь видит |
| «Удалить урок» (свой разовый до начала) | да, существующая отмена урока автором (`POST /org/groups/{id}/attendance` со `status: "cancelled"`); после начала — 409 `LESSON_ALREADY_STARTED` | да (обычная отмена) |
| Перенести | как сейчас | как сейчас |

Удаление отработки (отмена разового урока) освобождает отменённый оригинал: по нему можно снова назначить отработку и вернуть урок.

## 6. Другие ручки, у которых появились отказы

| Ручка | Отказ |
|---|---|

## 7. Перенос

Перенос отработки/дополнительного копирует `purpose`, `money`, `madeUp*` и автора на копию; у отработки указатель оригинала переходит на копию. Копия переноса обычного урока — `purpose = moved` (как раньше, ничего не меняется).

## 8. Ведомость зарплаты (только владелец)

- Новые состояния клетки урока (`marks[].state`): `undecided` («не решено», в сумму не входит, отдельным тоном) и `no_pay` («без оплаты», 0). Остальные — как прежде (`counted`, `unpaid`, `excused_confirmed`, `excused_pending`, `not_in_group`). У новых состояний `divisor` / `price` / `cover` пусты, `mark` = 0. Правило «входит в сумму» по-прежнему на сервере: в сумму входят только `counted` и `excused_pending`; фронту ничего не пересчитывать.
- Состояние ставится на каждого ученика урока, который засчитывается по обычному правилу (в составе, «был / опоздал / не был», уважительная без подтверждённой справки). Подтверждённая справка остаётся `excused_confirmed`, не из состава — `not_in_group`.
- У строки (`lines[]`) добавлены счётчики `undecided` и `no_pay` (число клеток); у листа — `undecided_total` (клеток «не решено» на листе).
- В обзоре месяца у преподавателя — `undecided_lessons`: сколько проведённых уроков ждёт решения (считаются уроки, не клетки).
- Состояние приходит от урока: дополнительный `wait` → `undecided`, `none` → `no_pay`, `paid` → обычное `counted` (деньги «как до начала учёта»: цена ученика на день урока, делитель месяца, баланс ученика не меняется). **Отработка (v4) — всегда как обычный урок** (`counted` по отметкам), в том числе пустая; `undecided` / `no_pay` у отработки не бывает.
- Отработка: покрытие и цена — по дате отработанного урока (не по дате отработки), для календарных способов оплаты. Если между ними сменился способ оплаты с календаря на пакет — отработка не списывает пакет ученика.
- Выгрузка Excel: в клетках слова «не решено» / «без оплаты».
- Изменение состояния (решение) меняет «отпечаток» данных: сохранённая ведомость становится «данные изменились», разница показывается как обычно («доплатить / переплата»).
